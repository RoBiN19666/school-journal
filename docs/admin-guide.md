# Руководство администратора

Документ для человека, который устанавливает и обслуживает журнал: он не требует
знания Django. Команды можно копировать целиком — они выполняются в папке проекта
(там, где лежат `docker-compose.yml` и `manage.py`).

Версия журнала — **2.41.1** (см. `journal/__init__.py` и `CHANGELOG.md`).

---

## 1. Что это и для кого

«Электронный журнал» — рабочий журнал посещаемости для организации дополнительного
образования: ученики, программы, группы с составом, расписание занятий, темы занятий
с академическими часами и отметки посещаемости (`P` — присутствовал, `A` — отсутствовал,
`L` — опоздал). Оценок в журнале нет — только посещаемость.

Из журнала выгружаются отчёты и таблицы (Excel и расписание картинкой PNG), а все данные
можно сохранить одним файлом — резервной копией. Этот документ — для администратора:
установка, первый запуск, обновление версии и резервные копии.

Разделы по ролям, правам, работе методиста, выгрузкам и безопасности — во второй части
руководства.

## 2. Требования и установка

### Что нужно

* **Docker** и **встроенный в него `docker compose`** (Docker Desktop на Windows или
  Docker Engine на сервере). Ничего больше ставить не надо: Python, PostgreSQL и все
  библиотеки живут внутри контейнеров.
* Свободный порт **8000** на машине.
* Файл `.env` в папке проекта — в нём настройки журнала.

Сервисов два (см. `docker-compose.yml`):

| Сервис | Что это | Контейнер |
| --- | --- | --- |
| `db` | PostgreSQL 16, данные в томе `postgres_data` | `school_journal_db` |
| `web` | само приложение (gunicorn на порту 8000), загруженные логотип и значок — в томе `media_data` | `school_journal_web` |

При старте контейнера `web` автоматически выполняется `entrypoint.sh`: применяются миграции
базы, собирается статика, затем запускается сервер. Отдельно запускать миграции не требуется.

### Файл `.env`

Шаблон всех настроек — файл `.env.example` в корне проекта: `install.sh` (или
`install.ps1` в Windows) копирует его в `.env` и заполняет секреты. При ручной
установке скопируйте файл сами и заполните значения. Ниже — переменные, которые
**действительно читает** журнал. Если переменной нет, берётся значение по умолчанию;
там, где значения по умолчанию нет, журнал не запустится — об этом написано в колонке
«Если не задать».

**Обязательные (без них контейнер `web` не поднимется):**

| Переменная | Что это | Если не задать |
| --- | --- | --- |
| `SECRET_KEY` | длинный случайный ключ (не короче 50 символов). Им подписываются сессии и токены CSRF, им же шифруется пароль SMTP в настройках почты | при `DEBUG=0` журнал останавливается с сообщением «Не задан SECRET_KEY…». Ключ должен быть не короче 50 символов и не из одинаковых символов. Сгенерировать новый: `python -c "import secrets;print(secrets.token_urlsafe(64))"` |
| `ALLOWED_HOSTS` | домены журнала через запятую, например `journal.example.ru,localhost,127.0.0.1` | при `DEBUG=0` журнал останавливается с сообщением «Не задан ALLOWED_HOSTS…» |
| `DEBUG` | `0` — рабочий режим, `1` — локальная отладка (подробные ошибки) | `docker compose` откажется стартовать и попросит задать `DEBUG=0` или `DEBUG=1`. **В интернете всегда `0`** |

Остальные переменные (все — из `docker-compose.yml` и `school_journal/settings.py`):

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | `school_journal` | имя базы, пользователь и пароль PostgreSQL |
| `POSTGRES_HOST`, `POSTGRES_PORT` | `db`, `5432` | адрес базы (в `docker-compose.yml` жёстко задан `db`) |
| `DEMO_MODE` | `1` (так задано в `.env`; при `DEBUG=1` включается сам) | `1` — тестовый режим: вход без пароля как методист и преподаватель на отдельной демо-базе. **Перед реальной работой поставьте `0`** |
| `DEMO_DB_NAME` | `school_journal_demo` | имя отдельной демонстрационной базы (боевых данных не касается) |
| `DEMO_SQLITE_NAME`, `DB_SQLITE_NAME` | `db_demo.sqlite3`, `db.sqlite3` | имена файлов баз только для запуска без Docker (`DB_ENGINE=sqlite`) |
| `DB_ENGINE` | `postgres` | `sqlite` — локальный запуск без PostgreSQL |
| `DB_CONN_MAX_AGE` | `60` | сколько секунд держать соединение с базой открытым |
| `TIME_ZONE` | `Europe/Moscow` | часовой пояс журнала (в `.env` указан `Asia/Yekaterinburg`) |
| `FUND_NAME` | значение из `school_journal/settings.py` | название организации на странице входа и в подвале |
| `ADMIN_URL` | `admin/` | адрес админки Django (в `.env` — `secret-admin-panel/`, чтобы сканеры её не находили) |
| `SESSION_COOKIE_AGE` | `43200` (12 часов) | время жизни сессии без галочки «Сохранить вход», секунд |
| `REMEMBER_ME_DAYS` | `30` | срок входа с галочкой «Сохранить вход», дней (журнал принимает 1–90) |
| `DATA_UPLOAD_MAX_MEMORY_SIZE`, `DATA_UPLOAD_MAX_NUMBER_FIELDS` | 8 МБ, `5000` | ограничения на размер загружаемого файла копии и число полей формы |
| `TAILWIND_CDN` | `0` | `1` — брать стили с CDN вместо файла внутри проекта (интернет для интерфейса не нужен) |
| `TRUST_PROXY_HEADERS` | `0` | `1` — доверять заголовкам `X-Forwarded-*` от nginx/прокси |
| `SECURE_SSL_REDIRECT` | `0` | `1` — перенаправлять `http` на `https` |
| `SESSION_COOKIE_SECURE`, `CSRF_COOKIE_SECURE` | как у `SECURE_SSL_REDIRECT` | cookie только по HTTPS |
| `SECURE_HSTS_SECONDS` | `0` (при редиректе — год) | HSTS |
| `CSRF_TRUSTED_ORIGINS` | свои домены из `ALLOWED_HOSTS` | дополнительные доверенные источники, например `https://journal.example.ru` |
| `LOG_LEVEL` | `INFO` | подробность записей в логах |
| `NOTIFY_EMAIL_BACKEND` | SMTP | транспорт писем-уведомлений (`console` — писать их в лог вместо отправки) |
| `DEFAULT_FROM_EMAIL` | `journal@localhost` | адрес отправителя писем |
| `NICE_ERRORS_IN_DEBUG` | `1` | `0` — показывать встроенную отладочную страницу Django вместо своей |
| `AUTO_BLOCK_PROBES`, `AUTO_BLOCK_THRESHOLD`, `AUTO_BLOCK_WINDOW_MINUTES`, `AUTO_BLOCK_HOURS`, `AUTO_BLOCK_PRIVATE` | вкл., `5`, `15`, `24`, выкл. | авто-блокировка адресов, которые сканируют чужие пути |
| `PYTHON_IMAGE`, `POSTGRES_IMAGE` | `python:3.12-slim`, `postgres:16-alpine` | базовые образы. Если сборка падает с `TLS handshake timeout`, укажите зеркало, например `dockerhub.timeweb.cloud/library/python:3.12-slim` |

### Установка

1. Скопируйте папку проекта на машину, где установлен Docker.
2. Откройте `.env` и проверьте три обязательные переменные: `DEBUG=0`, свой `SECRET_KEY`
   (50+ символов), свои домены в `ALLOWED_HOSTS`. Для реальной работы поставьте `DEMO_MODE=0`.
3. В папке проекта выполните:

```bash
docker compose up -d --build
```

Ключ `-d` запускает контейнеры в фоне, `--build` — заново собирает образ приложения.
Первая сборка занимает несколько минут: скачиваются образы и ставятся библиотеки.
Строка «==> Применяю миграции…» в логах означает, что база обновляется автоматически.

4. Если нужно применить миграции вручную (например, после восстановления из копии):

```bash
docker compose exec web python manage.py migrate
```

5. Проверка работоспособности — самопроверка журнала:

```bash
docker compose exec web python manage.py healthcheck
```

Команда ничего не меняет и не требует открытого браузера. Она печатает строку `[OK]`
или `[ОШИБКА]` по каждой проверке: база данных, применённые миграции, основные таблицы,
файлы оформления, шаблоны, темы, настройки оформления, демонстрационная база, права на
запись в папку загрузок, полные имена преподавателей, разовые занятия. В конце — итог:

```
[OK] База данных: соединение есть (postgresql, school_journal)
...
[OK] Разовые занятия: разовых занятий с датой: 0, все совпадают с днём недели
[ИНФО] Journal version: 2.41.1; часовой пояс: Asia/Yekaterinburg; USE_TZ: да; Django: 5.0.x
Checks: 11, errors: 0
```

Ожидаемый результат — **«Checks: 11, errors: 0»**. Если ошибок больше нуля, команда
завершается с кодом 1: строки `[ОШИБКА]` показывают, что именно не так (например,
«не применено миграций: 1» или «не найдены файлы»). Демонстрационная база при
выключенном `DEMO_MODE` даёт строку «демо-режим выключен» — это не ошибка.

6. Откройте журнал в браузере: `http://localhost:8000` (или адрес из `ALLOWED_HOSTS`).

## 3. Первый запуск

Пока в базе нет ни одного активного администратора, любая страница журнала ведёт на экран
первоначальной настройки — `/setup/`. Настроенным журнал считается тогда, когда в нём есть
хотя бы один **активный** администратор: учётная запись с ролью «Главный администратор» или
«Администратор» либо суперпользователь Django. Отключённые учётные записи не считаются:
журнал, где остались только преподаватели и методисты, всё ещё требует настройки.

Что заполняется на `/setup/`:

**Учётная запись (главный администратор, он же владелец журнала):**

* **Логин** — только латиница, цифры и символы `@ . + - _`, без пробелов и кириллицы
  (например, `admin`). Этим логином вы будете входить в журнал.
* **Фамилия** и **Имя** — обязательны, заполняются по-русски.
* **Отчество** и **Почта** — по желанию; почта нужна, если администратор будет получать
  уведомления журнала.
* **Пароль** и **Повтор пароля** — проверяются правилами Django: не короче 8 символов,
  не только из цифр, не слишком распространённый и не похожий на логин. «Пароли не совпадают» —
  сообщение о том, что два поля различаются.

**Оформление журнала:**

* **Название журнала** — показывается в заголовке, на странице входа и в подвале.
* **Название организации**.
* **Короткий знак (логотип текстом)** — 1–4 знака, если картинку загружать не хотите;
  пустое поле превращается в «ЭЖ».
* **Логотип** и **Значок (favicon)** — картинки PNG, JPG, WEBP или ICO, каждая не больше 1 МБ.
  Загруженные файлы хранятся в томе `media_data` и переживают обновления журнала.

После отправки формы журнал создаёт учётную запись с ролью «Главный администратор»,
сразу выполняет вход и открывает сводку. Повторно мастер не появится: пока в журнале есть
активный администратор, адрес `/setup/` просто переводит на сводку.

### Если администратора нужно создать командой

Штатный путь для нового журнала — экран `/setup/`. Но администратора можно создать и из
консоли, например если базу переносили или учётную запись потеряли:

```bash
docker compose exec web python manage.py createsuperuser
```

Команда спросит логин (латиницей), почту (можно оставить пустой) и пароль дважды.
Учётная запись создаётся с ролью «Главный администратор». Полезные дополнения:

```bash
docker compose exec web python manage.py changepassword admin
```

меняет пароль уже существующей учётной записи (вместо `admin` — её логин).
Остальные сотрудники (администраторы и методисты) заводятся в самом журнале, в разделе
**«Сотрудники УМО»** — командой их создавать не нужно.

> Журнал не даёт остаться без администратора: выключить, понизить или удалить последнего
> активного администратора нельзя — появится сообщение «Нельзя оставить журнал без
> администратора. Сначала назначьте другого администратора.»

## 4. Обновление версии

Порядок:

1. **Скачайте резервную копию** — раздел **«Резервная копия»** в журнале (см. раздел 5).
   Это обязательный шаг: копия — единственный быстрый способ вернуть данные.
2. Замените файлы проекта на новую версию (кроме `.env`: свои настройки и `SECRET_KEY`
   переносятся как есть).
3. Соберите и запустите новую версию:

```bash
docker compose up -d --build
```

   Миграции базы применяются автоматически при старте контейнера `web`. Если хотите
   применить их отдельно:

```bash
docker compose exec web python manage.py migrate
```

4. Проверьте журнал:

```bash
docker compose exec web python manage.py healthcheck
```

   В конце должно быть «Checks: 11, errors: 0».

5. Откройте журнал в браузере и нажмите **Ctrl+F5** (принудительное обновление страницы):
   так браузер заново скачает стили и скрипты новой версии, а не возьмёт их из кэша.

**Где смотреть историю изменений.** Файл `CHANGELOG.md` в корне проекта: записи идут от
новой версии к старой, формат `МАЖОР.МИНОР.ПРАВКА`. Текущая версия журнала видна в двух
местах: в выводе `healthcheck` (строка `[ИНФО] Версия журнала: …`) и в подвале каждой
страницы журнала (страница «О продукте» — адрес `/about/`).

**Если после обновления что-то не так.**

* Посмотрите, что именно проверка считает ошибкой: строки `[ОШИБКА]` в `healthcheck`
  называют причину («не применено миграций», «не найдены файлы», «не собираются шаблоны»).
* Посмотрите логи приложения — там трассировка ошибки и ответы сервера:

```bash
docker compose logs --tail 200 web
```

* Проверьте, что оба контейнера подняты и база отвечает:

```bash
docker compose ps
docker compose exec db pg_isready -U school_journal
```

* Если журнал не открывается или данные выглядят испорченными — восстановите данные из
  копии, скачанной на шаге 1 (раздел 5).
* Если ошибка появилась после замены файлов, а откат проще, чем разбор: верните прежнюю
  версию файлов проекта и снова выполните `docker compose up -d --build`. Данные в томе
  `postgres_data` при обновлении и откате файлов не удаляются.

> `docker compose down` останавливает журнал, данные сохраняются.
> `docker compose down -v` **удаляет том с базой данных вместе со всеми данными** —
> используйте его, только если действительно хотите начать с пустого журнала.

## 5. Резервные копии и восстановление

Раздел **«Резервная копия»** доступен администраторам (главному администратору и
администратору) и открывается по адресу `/backup/`.

### Как скачать копию

1. Откройте **«Резервная копия»**. Слева видно, сколько сейчас в журнале учеников, программ,
   групп, занятий, отметок и пользователей.
2. При желании введите **парольную фразу**. С фразой файл скачается как
   `school_journal_backup_ГГГГММДД_ЧЧММ.json.enc` и будет зашифрован (PBKDF2 + HMAC).
   Без фразы — обычный файл `school_journal_backup_ГГГГММДД_ЧЧММ.json`.
3. Нажмите **«Скачать резервную копию»**. Файл собирается в момент скачивания — это
   актуальные данные на текущую минуту.

**Что внутри.** Один файл JSON со всеми данными журнала: учебные годы и полугодия, адреса
и кабинеты, пользователи, ученики, программы, группы с составом, расписание (включая разовые
занятия и подмены), отметки посещаемости, темы занятий с часами, участие в конкурсах и курсы
повышения квалификации педагогов. В конце файла есть раздел со счётчиками — сколько записей
в каждом разделе. Логотип и значок в копию не входят: они лежат в томе `media_data`.

**Почему файл нельзя передавать по открытым каналам.** В разделе «пользователи» лежат
**хеши паролей** всех учётных записей. Это не сами пароли, но по ним можно подбирать пароль,
а сама копия содержит полный список людей журнала. Поэтому: не отправляйте файл по почте,
в мессенджерах и не выкладывайте в общие облачные папки. Скачивайте либо с парольной фразой
(тогда без фразы файл не прочитать), либо храните на защищённом носителе. Парольную фразу
журнал нигде не сохраняет — потеряете её, и копию будет не восстановить.

### Как восстановить копию

1. Откройте **«Резервная копия»**, блок справа.
2. Выберите файл копии (`.json` или `.json.enc`). Для зашифрованной копии укажите ту же
   парольную фразу, с которой её скачивали.
3. Выберите режим:
   * **«Добавить и обновить»** — безопасный режим: данные из копии добавляются,
     существующие обновляются, ничего не удаляется.
   * **«Полностью заменить»** — данные журнала удаляются и загружаются из копии заново.
     Для этого режима нужно отметить галочку **«Подтверждаю полную замену данных»**,
     иначе журнал откажется выполнять восстановление.
4. Нажмите **«Восстановить»**.

Перед восстановлением журнал показывает сравнение, например:
«Всего записей в копии: 4210, в базе сейчас: 3980. Сравнение по разделам — учеников: в копии 512,
было 498; отметок посещаемости: в копии 3100, было 2950; …». Это подтверждение: видно, что
именно добавится или заменится. После восстановления такое же сравнение выводится в отчёте,
а событие записывается в журнал безопасности с отправкой уведомления.

**Чем режимы отличаются.**

| | «Добавить и обновить» | «Полностью заменить» |
| --- | --- | --- |
| Данные журнала (ученики, программы, группы, расписание, отметки, темы, конкурсы, курсы) | добавляются; существующие обновляются, лишнее остаётся | **полностью заменяются** данными копии |
| Учётные записи людей | добавляются и обновляются | **остаются**: не удаляются, только добавляются и обновляются из копии |
| Пустая копия | применится (ничего не добавит) | отказ: «Копия пуста… данные журнала не изменены» |
| Галочка подтверждения | не нужна | обязательна |

Учётные записи при полной замене сохраняются осознанно: иначе преподаватель или методист,
которого нет в копии, пропал бы вместе со своими занятиями и курсами. Кроме того:

* **своя учётная запись** при восстановлении не меняется — вы не потеряете доступ;
* роль, пароль и включённость **уже существующего администратора** копия не переписывает;
* если в копии есть **главный администратор**, эта часть пропускается: восстановить её может
  только сам главный администратор. В отчёте появится предупреждение «В копии есть главный
  администратор — эта часть пропущена».

**Как читать сравнение «в копии N, было M».** Для каждого раздела показывается пара чисел:
`N` — сколько записей этого раздела в загруженном файле копии, `M` — сколько их было в базе
непосредственно перед восстановлением. Сравнение выводится по разделам «ученики»,
«программы», «группы», «занятия», «отметки посещаемости», «темы занятий», «конкурсы»,
«курсы педагогов». Если `N` больше `M` — из копии придут новые записи; если меньше — в копии
их заметно меньше, чем было в базе (для режима «Полностью заменить» это значит, что часть
данных будет удалена). Пропущенные при разборе записи попадают в отдельный счётчик
«пропущено записей» — так помечаются строки копии, которые нельзя восстановить (например,
отметка без занятия или без ученика).

Если файл повреждён, это не опасно: журнал проверяет копию **до** любых изменений и при
проблеме отказывает, ничего не удаляя. Так выглядят типичные отказы: «Файл не похож на
резервную копию журнала…», «Копия версии N не поддерживается: текущий формат — 10»,
«Копия повреждена или неполна: нет обязательных разделов…», «Файл не является корректным JSON…».

## 6. Пользователи и роли

Роль — это поле «Роль» в карточке учётной записи. От неё зависит, какие пункты меню видит
человек и что он может изменить. Ролей четыре.

### Кто что может

**Преподаватель.** Пункты меню «Мои занятия», «По неделям: темы и часы», а также доступные
всем вошедшим «Участие в конкурсах», «Повышение квалификации» и «Мои данные».

* Открывает и отмечает **только свои занятия**: страница отметок чужого занятия отдаёт
  страницу «Такой страницы нет» (404).
* В «Участии в конкурсах» видит и правит только те записи, которые внёс сам; в «Повышении
  квалификации» — только свои записи.
* В «Моих занятиях» есть кнопка «Выгрузить посещаемость в Excel» — личная выгрузка по своим
  занятиям активного полугодия.
* **Не видит**: «Сводка», «Ученики», «Преподаватели», «Отсутствия», «Программы и группы»,
  «Расписание», «Учебные периоды», «Посещаемость», «Темы занятий»,
  «Выгрузка в Excel», «Сотрудники УМО», «Безопасность», «Резервная копия»,
  «Демо-режим и демо-данные», «Кастомизация», «Админка Django».

**Методист.** Ведёт учёт:

* «Сводка», «Ученики», «Преподаватели» (создаёт и правит преподавателей), «Отсутствия»
  (больничные и командировки преподавателей, см. раздел 15), «Программы и группы»,
  «Расписание», «Учебные периоды»;
* «Посещаемость» и «Темы занятий» — видит и правит темы и отметки любых занятий;
* «Участие в конкурсах» и «Повышение квалификации» — все записи;
* «Выгрузка в Excel», «Мои данные».
* **Не видит**: «Сотрудники УМО», «Безопасность», «Резервная копия», «Демо-режим
  и демо-данные», «Кастомизация», «Админка Django».
* Статистика журнала событий на «Сводке» показывается только администраторам.
* Удалять учебные годы методист не может: раздел отвечает «Удалять учебные годы может только
  администратор: вместе с годом удаляются его полугодия, группы, занятия и отметки.»

**Администратор.** Всё то же, что у методиста, плюс:

* «Сотрудники УМО» — создание учётных записей методистов и администраторов, смена ролей,
  выключение и сброс пароля;
* «Безопасность» — почта и уведомления, доступ по IP-адресам, журнал заходов;
* «Резервная копия» — скачивание и восстановление;
* «Демо-режим и демо-данные»;
* «Админка Django» — адрес задаётся переменной `ADMIN_URL` (по умолчанию `admin/`, в `.env`
  проекта — `secret-admin-panel/`);
* статистика посещений на «Сводке».
* **Не видит** «Кастомизация»: журнал отвечает «Кастомизация доступна только главному
  администратору.»

**Главный администратор.** Всё то же, что у администратора, плюс «Кастомизация». Кроме того:

* его карточку может править только он сам: «Править главного администратора может только
  он сам.»;
* роль «Главный администратор» в списке ролей назначает только он; остальные администраторы
  видят в списке лишь «Методист (сотрудник УМО)» и «Администратор»;
* часть резервной копии, где есть главный администратор, восстанавливает только он (раздел 5).

Если прав на раздел нет, журнал пишет «Недостаточно прав для этого раздела.» и возвращает
человека на его домашнюю страницу.

### Как создать преподавателя

1. Откройте **«Преподаватели»** и нажмите **«Добавить преподавателя»**.
2. Заполните: **Логин** (латиница, без пробелов, например `ivanov`), **Фамилия**, **Имя**,
   **Отчество** (по желанию), **Пароль** и **Повтор пароля**.
3. Нажмите **«Создать»**. Роль «Преподаватель» журнал проставит сам.
4. На странице списка появится жёлтый блок **«Пароль для ‹ФИО› (логин ‹логин›)»** — см.
   «Как выдаётся пароль» ниже.

Создавать и править преподавателей могут методист и администратор. Позже данные и пароль
меняются в карточке преподавателя — кнопка **«Изменить данные и пароль»** в списке.

### Как создать сотрудника УМО

1. Откройте **«Сотрудники УМО»** (раздел виден только администраторам) и нажмите
   **«Добавить сотрудника»**.
2. Заполните **Логин**, **Фамилия**, **Имя**, **Отчество**, выберите **Роль**
   («Методист (сотрудник УМО)» — подставлена по умолчанию, либо «Администратор»), задайте
   **Пароль** и **Повтор пароля**.
3. Нажмите **«Создать»**. Журнал покажет: «Сотрудник создан. Передайте ему логин и пароль —
   он войдёт на этой же странице входа.»
4. Пароль один раз показывается в жёлтом блоке над списком (с кнопкой «Скопировать»).
5. Дальше сотрудник входит по адресу журнала и попадает на «Сводку». Роль, выключение
   учётной записи и новый пароль меняются в его карточке («Сотрудники УМО» → ФИО).

### Как выдаётся пароль

* В форме создания (преподавателя и сотрудника) есть кнопка **«Сгенерировать пароль»**:
  она заполняет оба поля пароля и показывает получившийся пароль в рамке, рядом появляется
  кнопка **«Скопировать»**. Пароль — 12 знаков, в нём есть и строчные, и прописные буквы,
  цифра и символ; похожие друг на друга знаки не используются. Подсказка под кнопками:
  «Запишите или скопируйте пароль сейчас — после сохранения он больше не отобразится.»
* **«Скопировать»** кладёт пароль в буфер обмена; если браузер этого не разрешает, откроется
  окно с паролем — скопируйте его оттуда вручную.
* После сохранения пароль **один раз** показывается в жёлтом блоке на странице списка
  («Преподаватели» или «Сотрудники УМО») с кнопкой «Скопировать». При обновлении страницы
  блок исчезает — в базе хранится только необратимый хеш пароля, посмотреть его нельзя.
* Если пароль потерян, администратор задаёт новый: карточка преподавателя → блок
  **«Смена пароля»** → **«Сохранить новый пароль»**; карточка сотрудника → **«Смена пароля»**
  → **«Сменить пароль»**. Старый пароль при этом не нужен, новый тоже показывается один раз
  в списке.

### Правила учётных записей

| Правило | Что произойдёт при нарушении |
| --- | --- |
| Логин — только латиница, цифры и символы `@ . + - _`, без пробелов и кириллицы | «Логин может содержать только латинские буквы, цифры и символы @ . + - _ (без пробелов и кириллицы)» |
| Имя и фамилия обязательны | «Укажите имя.» / «Укажите фамилию.» |
| Пароль по правилам Django: не короче 8 символов, не только из цифр, не слишком распространённый, не похож на логин | форма не сохранится и покажет причину; «Пароли не совпадают.» — если два поля различаются |
| Нельзя выключить собственную учётную запись | «Нельзя выключить свою учётную запись — вы потеряете доступ к журналу. Попросите другого администратора.» |
| Нельзя выключить, понизить в роли или удалить **последнего активного администратора** | «Это единственный активный администратор. Сначала назначьте другого администратора.» (проверка стоит и в формах, и на уровне модели — в том числе в админке Django и в командах) |
| Карточку главного администратора правит только он сам | «Править главного администратора может только он сам.» |

Выключение учётной записи ничего не удаляет: человек со всеми своими занятиями, темами
и отметками остаётся в базе, но войти в журнал не может, и в списках выбора при создании
расписания и программ он больше не появляется (в карточке при этом видно, сколько занятий
и программ за ним закреплено).

### Как сменить свой пароль

1. Откройте меню под своим именем в правом верхнем углу → **«Мои данные»** (адрес `/profile/`).
2. Блок **«Смена пароля»**: введите **Старый пароль**, **Новый пароль**, **Подтверждение
   нового пароля**. Тут же работает кнопка «Сгенерировать пароль».
3. Нажмите **«Сменить пароль»**. Журнал ответит «Пароль изменён — используйте его при
   следующем входе.»

В том же разделе меняются свои ФИО (блок «Фамилия и имя»), а ниже выбирается тема оформления
(см. раздел 10). Логин, роль и почта в «Моих данных» не меняются.

## 7. Рабочий процесс методиста

Порядок такой: сначала период и адрес, потом справочники, затем ученики, программы, группы,
расписание. Темы и отметки появляются уже после занятий (раздел 8).

### Шаг 1. Учебный год и полугодия

В шапке каждой страницы есть переключатели **«учебный год»**, **«полугодие»** и **«адрес»**
(адрес виден всем, кроме преподавателя). Выбранное запоминается для вашей учётной записи
и действует на всех страницах. Рядом с полугодием стоит метка «текущая по дате» или «выбрана
вручную»; во втором случае есть кнопка «↺ к текущему периоду», которая возвращает период,
в который попадает сегодняшняя дата.

Раздел **«Учебные периоды»** (`/periods/`):

* Сверху — блок **«Учебные годы»**: годы выводятся плитками сеткой по 3–4 в ряд (поле
  «Найти год…» фильтрует список по названию), а сам список — постранично, тем же размером
  страницы, что и остальные списки журнала («10, 25, 50, 100» — см. шаг 3). Годы журнал
  заводит сам: он заранее создаёт предыдущий, текущий и два будущих года, чтобы расписание
  готовили заранее. Если годов ещё нет, список подсказывает: «Учебные годы появятся здесь
  автоматически.»
* Блок **«Добавить учебный год»**: выбирается только год, начало (1 сентября) и окончание
  (31 августа) подставляются сами; кнопка **«Добавить год»**. Новый год сразу получает
  два полугодия: «Учебный год 2026–2027 создан вместе с двумя полугодиями.»
* Справа таблица **«Полугодия»**: номер, «Начало», «Окончание», а также счётчики программ
  и групп, ссылка «пусто — перенести» (если программ в полугодии нет) и кнопка
  **«Сохранить даты полугодий»**.

**Проверки полугодий.** Сохранить даты не получится, если:

* не заполнены номер и обе даты;
* окончание раньше начала или совпадает с ним («окончание должно быть позже начала»);
* полугодие выходит за границы своего учебного года — сообщение называет и даты полугодия,
  и границы года: «выходит за границы учебного года … Укажите даты внутри учебного года.»;
* двум полугодиям указан один номер: «Номер 1 указан у двух полугодий…»;
* полугодия одного года **пересекаются** — сообщение перечисляет общие дни: «Полугодия
  1 полугодие (…) и 2 полугодие (…) пересекаются: общие дни с … по …. Полугодия одного
  учебного года не должны пересекаться.»;
* порядок по номерам расходится с порядком по датам: «Порядок по номеру не совпадает
  с порядком по датам…».

Те же проверки сторожат и саму запись в базу — неверные даты не попадут в журнал ни через
форму, ни через админку Django, ни из кода. При ошибке в базе ничего не меняется, а текст
ошибки виден сообщением на странице.

Полугодие, которое идёт сейчас по календарю, помечается как текущее. Программы, группы,
расписание и посещаемость привязаны к конкретному полугодию и адресу, поэтому в новом
полугодии данных нет — их переносят (шаг 8).

### Шаг 2. Адреса и кабинеты

Адрес — это филиал («ул. Примерная, 1», «ул. Вторая, 10»). Переключается он в шапке, а список
адресов и кабинетов журнал создаёт сам при первом обращении: «ул. Примерная, 1» с кабинетами
(«Класс информатики и математики (1 этаж)», «Лаборатория биологии», «Лаборатория химии»,
«Учебный класс (2 этаж)», «Лаборатория физики», «Конференц-зал») и «ул. Вторая, 10»
с кабинетами «№1», «№2», «№11», «№13».

Добавить или переименовать адрес и кабинет можно в **«Админке Django»** (раздел
«Электронный журнал» → «Адреса (филиалы)» и «Кабинеты»): у кабинета указывается адрес
и порядок вывода. В самом журнале адреса и кабинеты выбираются, но не создаются. Кабинеты
принадлежат адресу: у занятия не получится выбрать кабинет чужого адреса (журнал скажет,
к какому адресу относится кабинет), а одинаковые названия кабинетов внутри одного адреса
не допускаются.

### Шаг 3. Ученики

Раздел **«Ученики»**:

* **«Добавить ученика»** — фамилия, имя, отчество (по желанию), дата рождения (по желанию,
  с подсказкой «Можно не заполнять») и поле **«Отпускать ребёнка во время беспилотной
  опасности»**: `Н` («Нет заявления»), `ЕН` («Есть заявление, не отпускать»), `ЕО` («Есть
  заявление, можно отпускать»). Этот код виден педагогу в журнале посещаемости и попадает
  в выгрузки.
* Поиск по фамилии, имени и отчеству — по всей базе.
* **«Импорт из Excel»** — загрузка списка детей: выберите файл, при необходимости группу
  и галочку пропуска дублей, нажмите **«Загрузить и проверить»**. Перед сохранением журнал
  показывает разобранный список («Проверьте список»): строки с пометкой «уже в базе» можно
  оставить без галочки, тогда они не импортируются. После подтверждения журнал сообщает,
  сколько учеников добавлено и сколько уже было в базе.
* Удаление ученика убирает и его отметки посещаемости (журнал показывает, из скольких групп
  он будет исключён и сколько отметок удалится). Если ребёнок просто ушёл из группы, лучше
  убрать его из состава группы, а не удалять карточку.

Списки в журнале постраничные: 10, 25, 50 или 100 записей на страницу, выбранное значение
запоминается для всех списков.

### Шаг 4. Программы

Раздел **«Программы и группы»** показывает программы **активного полугодия и активного
адреса** (сколько программ есть в других полугодиях и адресах, журнал подсказывает отдельной
строкой).

**«Добавить программу»**: название, «Основной преподаватель» (обязательное поле) и
«Преподаватели программы» — те, кто может вести занятия и подменять друг друга. Программы
не общие: у каждого полугодия и каждого адреса свои, поэтому программа создаётся в активном
полугодии и адресе, а одинаковое название в одном полугодии и адресе не допускается.
Преподавателей позже можно добавить или убрать в карточке программы.

### Шаг 5. Группы и состав группы

* Группа создаётся из карточки программы: **«Добавить группу»**. Группа сразу относится
  к полугодию и адресу своей программы.
* **«Состав группы»** (кнопка у группы) — постраничный список всех учеников базы
  (10/25/50/100 на страницу, по умолчанию 25), поле поиска ищет **по всей базе**, а не только
  по видимой странице. Отметьте нужных галочками и нажмите «Сохранить». Журнал подтвердит:
  «Состав группы «…» сохранён: N уч. (в группе всего M).»
* Ученики, которые уже в группе, но не попали на открытую страницу, при сохранении не
  теряются. Удаление группы удаляет её занятия и отметки; сами ученики остаются в базе.

### Шаг 6. Расписание

Раздел **«Расписание»** показывает занятия активного полугодия и адреса двумя способами:
таблицей «время × дни недели» и списком по дням (переключатель вида). Фильтр по программе —
сверху. Занятия можно добавлять, править и удалять.

**«Добавить занятие»** — поля:

| Поле | Что учесть |
| --- | --- |
| Группа | только группы активного полугодия и адреса |
| Преподаватель занятия | список — преподаватели выбранной программы (основной и остальные ведущие); если преподавателя не выбрать, подставится основной |
| Кабинет | только кабинеты адреса программы занятия |
| День недели | для обычного занятия, которое повторяется каждую неделю |
| Дата разового занятия | заполняется, если занятие проходит один раз (мероприятие): день недели тогда считается по дате |
| Начало, Окончание | время у каждого занятия своё; окончание подставляется через 90 минут и его можно изменить |
| «1. Не учитывать занятость преподавателя» | подсказка в форме: «Снимает проверку занятости преподавателя по времени; кабинет и группа проверяются». Отметка нужна, когда занятие осознанно ставится в уже занятое у преподавателя время — например, при подмене: занятость кабинета и группы проверяется всё равно |
| «2. Подмена (заменяющий преподаватель)» | подсказка в форме: «Занятие ведёт заменяющий преподаватель: в расписании — значок «подмена», его занятость проверяется». Занятость заменяющего проверяется как обычно: чтобы провести подмену в занятое у него время, отметьте отдельно «1. Не учитывать занятость преподавателя» |

**Обычные и разовые занятия.** Обычное занятие (дата не заполнена) повторяется каждую неделю
в свой день. Разовое занятие бывает только в указанную дату: в календаре и журналах оно
видно лишь в эту дату, а в расписании помечено «разовое · 12.10.2026». Дата разового занятия
должна попадать в полугодие группы, иначе журнал скажет: «Дата … вне полугодия группы…».

**Расписание показывает одну неделю** (по умолчанию текущую, листание — кнопками
«Предыдущая неделя» / «Текущая неделя» / «Следующая неделя» и параметром `?week=ГГГГ-ММ-ДД`):
разовые занятия и подмены видны только в свою неделю, а пометка «отсутствует: …» — по
показанной неделе (на текущей неделе ещё и ближайший будущий период). Недели листаются внутри
полугодия: на границах кнопки неактивны, а неделя из старой ссылки приводится к ближайшей
допустимой. Выбранная неделя и вид (сетка или список) сохраняются при переключении.

**Что проверяет журнал при сохранении:**

* **занятость преподавателя** — у него не может быть двух занятий в одно и то же время
  (проверка идёт внутри полугодия, но по всем адресам). Сообщение называет мешающее занятие
  и свободные окна: «У преподавателя … в это время уже занятие: 10:00–11:30 — … Свободно
  в этот день: 08:00–10:00, 11:30–21:00.»;
* **занятость группы** — «У группы в это время уже есть занятие.»;
* **занятость кабинета** — «Кабинет «…» занят: … Выберите другой кабинет или время.»
  (у разового занятия в сообщении указывается дата);
* окончание позже начала — «Окончание должно быть позже начала занятия.»;
* кабинет из адреса программы — иначе сообщение о том, какому адресу принадлежит кабинет;
* у программы указан преподаватель — иначе «У программы «…» не указан преподаватель.
  Назначьте его в разделе «Программы».»;
* выбранный преподаватель ведёт эту программу — иначе «… не ведёт программу «…». Добавьте его
  в карточке программы в списке преподавателей.»;
* для обычного занятия выбран день недели — «Выберите день недели или укажите дату разового
  занятия.»

**Помощь при выборе времени.** В форме занятия видно занятость выбранного преподавателя
по дням недели (занятые занятия и свободные окна), а для выбранного дня — занятость кабинетов
адреса: «свободен весь день», «занят частично», «занят весь день» с перечнем занятий. Рабочий
день для этой оценки — с 8:00 до 21:00, а окно короче 90 минут свободным не считается.

**Подмены.** Если занятие ведёт заменяющий преподаватель, поставьте галочку **«2. Подмена»** —
занятие помечается значком «подмена» в расписании и журналах. Проверку занятости преподавателя
по времени эта галочка не снимает: занятость заменяющего проверяется как у любого
преподавателя. Если подмена осознанно ставится в уже занятое у заменяющего время, отметьте
дополнительно **«1. Не учитывать занятость преподавателя»** — только она снимает проверку
по времени. Занятость кабинета и группы проверяется в обоих случаях всегда.

**Занятие ведёт только преподаватель программы.** В поле «Преподаватель занятия» и в поле
«3. Кого заменяют» список — это «Преподаватели программы» из карточки программы: основной
преподаватель и дополнительные. Если выбрать кого-то другого, форма не сохранится:
«‹ФИО› не ведёт программу «‹название›»: занятие может вести только преподаватель программы.
Добавьте его в карточке программы в списке «Преподаватели программы».». Исключение — уже
стоящее занятие: если преподаватель был назначен до этого правила, занятие правится и
сохраняется как есть, пока преподавателя не меняют.

### Шаг 7. Перенос данных из другого полугодия

Если начинается новое полугодие или открывается второй адрес, данные не заводят заново.
Откройте **«Учебные периоды»** → ссылка **«Перенести из другого полугодия»** (или ссылка
«пусто — перенести» у полугодия без программ).

1. Слева выберите **полугодие-источник** и **адрес-источник**.
2. Справа показано, куда переносим, — это активные полугодие и адрес; если они не те,
   переключите их в шапке страницы и вернитесь.
3. Отметьте галочками нужные группы (есть «Отметить все группы» и поиск по программе
   или группе). Галочки **«Состав учеников»** и **«Расписание»** включены по умолчанию.
4. Нажмите **«Перенести выбранное»**.

**Что переносится:**

* **программы** — создаются заново в целевом полугодии и адресе (программы не общие),
  вместе с основным преподавателем и остальными ведущими;
* **группы** — по названию; уже существующая группа используется, а не создаётся второй раз;
* **состав учеников** — ученики добавляются в группы; уже состоящие в группе не дублируются;
* **обычные занятия** — вместе с преподавателем, временем и кабинетами. Кабинет переносится
  по названию, если такой кабинет есть в целевом адресе; иначе занятие переносится
  **без кабинета** (об этом предупреждает подсказка в форме);
* **разовые занятия не переносятся** — они привязаны к конкретной дате другого полугодия,
  в отчёте появляется строка «разовых занятий не переносится: N».

**Что будет пропущено:** занятия, которые в целевом полугодии конфликтуют по времени
у преподавателя или по кабинету. Итог показывается отчётом: программ создано, групп создано,
использовано существующих, учеников добавлено, занятий создано, занятий пропущено, а также
список «Пропущено из-за занятости преподавателя» с расшифровкой. Повторный запуск переноса
ничего не дублирует: программы и группы ищутся по названию, одинаковые занятия пропускаются.
Перенос можно делать и внутри одного полугодия — на другой адрес.

## 8. Отметки и темы

### Как преподаватель отмечает посещаемость

1. **«Мои занятия»** (`/teacher/`) — расписание на текущую неделю по дням с датами; разовое
   занятие видно только в свою неделю. Нажмите на занятие — под ним написано
   «Отметить посещаемость →».
2. Откроется страница занятия. Сверху — «Предыдущее занятие» / «Следующее занятие»,
   «← неделю назад» / «через неделю →» и ссылка «вся неделя», ниже — календарь занятий группы
   (зелёные дни — дни, когда у группы есть занятие; сегодняшний день выделен) и список
   расписания группы.
3. В таблице у каждого ученика — три переключателя:

| Обозначение | Полное название в журнале | Короткая подпись на узком экране |
| --- | --- | --- |
| `P` | Присутствовал | Был |
| `A` | Отсутствовал | Нет |
| `L` | Опоздал | Опозд. |

Рядом с фамилией виден код БП (`Н`, `ЕН`, `ЕО`) и его расшифровка.

4. Нажмите **«Сохранить посещаемость»** — журнал ответит «Посещаемость сохранена.»

**Дата.** Отметки сохраняются отдельно для каждой даты (у отметки свой ключ: ученик, занятие,
дата). Если открыть дату, в которую занятия нет, журнал предупредит об этом и откроет
ближайшую подходящую дату: для обычного занятия — ближайший его день недели в пределах
полугодия, для разового — только его собственную дату.

**Снятие отметки.** Отдельной кнопки «снять отметку» на странице нет: журнал удаляет отметку
ученика за дату тогда, когда при сохранении в его строке не выбран ни один статус. В обычной
форме в каждой строке всегда выбран один из трёх статусов (у ученика без отметки —
«Присутствовал»), поэтому повторное сохранение просто перезаписывает отметку. Убрать отметки
целиком можно, удалив само занятие в **«Расписании»** (кнопка «Удалить») — вместе с занятием
уходят все отметки по нему; удаление группы, программы или ученика тоже удаляет связанные
отметки.

**Кто что может.** Преподаватель открывает только свои занятия: страница отметок чужого
занятия отдаёт «Такой страницы нет» (404). Методист и администратор открывают отметки любого
занятия — из «Посещаемости по неделям» по кнопке **«Отметить»**.

### Как заполняется тема занятия и как считаются часы

Темы заполняются в двух местах и одинаково:

* **«По неделям: темы и часы»** (преподаватель, пункт меню) — страница `/teacher/week/`;
* **«Посещаемость»** (методист и администратор) — страница `/weeks/`.

На этих страницах у каждого занятия есть поле **«Тема занятия»** (подсказка-пример:
«Например: Повторение дробей») и кнопка **«Сохранить тему»**. После сохранения журнал
подтверждает: «Тема сохранена: 12.10.2026, 2.00 акад. ч.» и показывает «заполнено: дд.мм.гггг
чч:мм». Если очистить поле и сохранить, тема удаляется («Тема удалена.» или «Тема не была
заполнена.»). На самой странице отметок тема только показывается: там написано, кто её
записал, и есть ссылка «Тема — в разделе «По неделям»», чтобы отметки и темы не путались.

**Часы считаются автоматически от времени занятия: 1 академический час = 45 минут.**
Занятие 10:00–11:30 (90 минут) даёт 2 акад. часа; часы хранятся с двумя знаками после
запятой и вручную не вводятся — при сохранении темы журнал пересчитывает их по занятию.
За неделю итог виден в шапке страницы: «занятий за неделю: 12 · академических часов: 24».

### Что видно методисту в недельном журнале

Раздел **«Посещаемость»** (`/weeks/`) показывает неделю с понедельника по субботу
(кнопки «Предыдущая неделя», «Текущая неделя», «Следующая неделя») и фильтры **«Группа»**,
**«Программа»**, **«Преподаватель»**.

**Листать можно только внутри полугодия.** Первая доступная неделя — та, в которую попадает
дата начала полугодия, последняя — та, в которую попадает дата окончания. На первой неделе
кнопка «Предыдущая неделя», а на последней — «Следующая неделя» показаны **неактивными**
(серыми, без ссылки): дальше занятий нет. «Текущая неделя» ведёт к неделе сегодняшнего дня, а
если сегодня вне полугодия — к ближайшей допустимой. Если в адресе указана неделя за границами
полугодия (например, по старой ссылке), журнал не отдаёт ошибку, а открывает ближайшую
допустимую и сообщает: «Эта неделя вне полугодия: показана ближайшая — 26.08.2024.». То же
поведение у страницы преподавателя **«По неделям: темы и часы»** (`/teacher/week/`).

По каждому занятию видно:

* день недели и дату, время занятия, программу и группу;
* преподавателя, значок «подмена» для подмен и дату у разового занятия;
* кабинет и адрес;
* академические часы занятия;
* счётчики «был: N», «нет: N», «опоздал: N», а если за эту дату отметок нет вовсе —
  пометку «не отмечено»;
* поле темы занятия и кнопку «Сохранить тему», а также фамилии учеников с цветом по статусу
  отметки и кодом БП;
* кнопку **«Отметить»**, которая ведёт на страницу отметок этого занятия за эту дату.

Сверху есть быстрые выгрузки: **«Выгрузить темы и часы в Excel»** (передаёт выбранные
фильтры — группу, программу, преподавателя) и **«Выгрузить посещаемость недели»** (передаёт
даты показанной недели).

Отдельный список **«Темы занятий»** (`/topics/`) — это журнал заполненных тем: поиск по теме,
фильтры по группе, преподавателю и периоду, сумма академических часов по найденным записям
и кнопка «Выгрузить в Excel». Темы здесь только смотрят — заполняются они на страницах недель.

## 9. Выгрузки и отчёты

Все отчёты собраны в разделе **«Выгрузка в Excel»** (`/export/`, пункт меню виден методисту
и администратору). Файлы — формат `.xlsx`, открываются в Excel, LibreOffice и Google Таблицах;
исключение — расписание картинкой (PNG).

**Общее ограничение охвата.** Почти все отчёты строятся по **активному полугодию и активному
адресу** — тем, что выбраны в шапке. Чтобы получить отчёт по другому адресу или полугодию,
переключите их в шапке и скачайте файл снова.

| Отчёт | Кнопка | Что попадает в файл | Охват | Кому доступен |
| --- | --- | --- | --- | --- |
| Ученики | «Скачать учеников» | лист «Ученики»: фамилия, имя, отчество, дата рождения, сколько групп, код БП, «Отпускать при беспилотной опасности», список групп; в шапке листа — расшифровка кодов БП | **все ученики базы**, без привязки к полугодию и адресу | методист, администратор |
| Программы и группы | «Скачать программы и группы» | лист «Программы» (программа, преподаватель, число групп) и лист «Группы» (программа, группа, полугодие, учеников, состав) | активные полугодие и адрес | методист, администратор |
| Расписание (Excel) | «Скачать расписание (Excel)» | лист «Расписание»: день недели, дата разового занятия, начало, окончание, программа, группа, кабинет, полугодие, преподаватель, учеников; сверху указаны адрес и год | активные полугодие и адрес | методист, администратор |
| Расписание картинкой | «Вертикальная картинка» / «Горизонтальная картинка» | PNG с таблицей «программа × дни недели»: преподаватель, кабинеты, занятия по дням, у разовых — дата; заголовок «РАСПИСАНИЕ» и подпись «Расписание на … учебный год · … полугодие» | активные полугодие и адрес | методист, администратор |
| Посещаемость | форма с фильтрами «Группа», «Программа», «Дата с», «Дата по» → «Скачать посещаемость» | два листа: отметки (с темой занятия и часами) и сводка по ученикам (был, нет, опоздал, всего отметок, часов) | активные полугодие и адрес; если даты не указаны — берётся период активного полугодия | методист, администратор |
| Темы занятий и академические часы | «Скачать темы занятий (Excel)» | лист «Темы занятий»: дата, день недели, начало, окончание, программа, группа, преподаватель, кабинет, тема занятия, академических часов | активные полугодие и адрес; можно сузить фильтрами (группа, программа, преподаватель) — на странице недель фильтры передаются в отчёт | методист, администратор |
| Участие в конкурсах | «Скачать участие в конкурсах (Excel)» | лист «Участие в конкурсах»: дата, название мероприятия, ФИО ученика, статус (победитель, призёр, участник), направление или программа, комментарий; лист «Сводка»: сколько записей по каждому статусу | **все записи** (по конкурсам нет привязки к полугодию и адресу); фильтры страницы (поиск, статус, даты) передаются в файл | все вошедшие: преподаватель — только внесённые им записи, методист и администратор — все |
| Курсы педагогов | «Скачать повышение квалификации (Excel)» | лист «Педагоги»: дата, вид, педагог, название программы, образовательная организация, часы, результат | **все записи**; фильтры страницы передаются в файл | все вошедшие: преподаватель — только свои записи, методист и администратор — все |
| Пользователи | «Скачать пользователей» | лист «Пользователи»: логин, фамилия, имя, роль, «Активен», «Доступ в админку», дата создания | все учётные записи журнала | только администратор и главный администратор (остальным кнопка не показывается) |

Дополнительно у преподавателя есть личная выгрузка: в разделе **«Мои занятия»** кнопка
**«Выгрузить посещаемость в Excel»** — файл называется «Моя посещаемость» и содержит отметки
только по его занятиям активного полугодия.

## 10. Оформление

### Где что меняется

**«Кастомизация»** (`/customization/`, пункт меню в блоке «Администрирование») — доступна
только главному администратору. Форма «Название и знаки», кнопка **«Сохранить настройки»**.
Справа — блок «Как это выглядит»: предпросмотр логотипа и значка, а также текущие значения.

| Поле | Что делает |
| --- | --- |
| **Название журнала** | показывается в заголовке, на странице входа и в подвале |
| **Название организации** | название организации в интерфейсе и подвале |
| **Короткий знак** | 1–4 знака, если картинку загружать не хотите (например, «ЭЖ»). Пустое поле заменяется на «ЭЖ» |
| **Логотип** | картинка вместо короткого знака |
| **Фавикон** | значок вкладки браузера |
| **Подсказка на странице входа** | строка-подсказка под формой входа |
| **Сохранять вход, дней** | сколько дней подставляется в надпись «Сохранить вход на N дней» на странице входа (журнал принимает 1–365; по умолчанию 30) |
| **Сессия без активности, часов** | сколько часов подставляется в подсказки про обычный вход (журнал принимает 1–720; по умолчанию 12) |

> Фактический срок жизни сессии задаётся не здесь, а переменными окружения в `.env`:
> `REMEMBER_ME_DAYS` (срок входа с галочкой «Сохранить вход», журнал принимает 1–90)
> и `SESSION_COOKIE_AGE` (обычный вход без активности, в секундах, по умолчанию `43200` —
> 12 часов). Поля «Кастомизации» меняют то, что человек видит на странице входа, поэтому
> держите их согласованными с `.env`.

### Форматы и ограничения

* Логотип и значок — **PNG, JPG, WEBP или ICO**, каждый файл **не больше 1 МБ**.
  Формат **SVG запрещён** (в нём может быть код), а файл дополнительно проверяется как
  настоящее изображение: «это не похоже на изображение. Нужен PNG, JPG, WEBP или ICO.»
* Загруженные файлы лежат в томе `media_data` и переживают обновления журнала. Отдаются
  наружу только картинки из папки `branding` — другие файлы по этому адресу недоступны.
* **Значения по умолчанию**, пока настройки не заданы: название журнала — «Электронный
  журнал», организация — значение переменной `FUND_NAME` (задано в
  `school_journal/settings.py`),
  короткий знак — «ЭЖ», подсказка на входе — «Ставьте галочку только на своём компьютере.»,
  «Сохранять вход» — 30 дней, сессия без активности — 12 часов.

### Темы

Тема выбирается самим пользователем: меню под именем → **«Мои данные»** → блок
**«Оформление»**. Доступны шесть тем:

| Тема | Подсказка |
| --- | --- |
| Светлая (по умолчанию) | Обычная светлая тема |
| Тёмная | Нейтральная тёмно-серая, для работы вечером |
| Ночная синяя | Глубокий синий, мягкий для глаз |
| Тёплая | Бежевая бумага, мягкий свет |
| Морская | Бирюзовый акцент и мягкий прохладный фон |
| Контрастная | Максимальная читаемость: чёрные границы и плотные кнопки |

Тема применяется сразу и запоминается **в этом браузере** (хранится в cookie `theme`,
на сервере не сохраняется). Как выглядят палитры, видно на картинке
`docs/themes-preview.png`.

## 11. Безопасность

Раздел **«Безопасность»** (`/security/`) виден администратору и главному администратору.
Сверху четыре плитки: «Ваш IP-адрес», «Неудачных входов всего», «Заблокированных попыток»
и «Режим» (включён ли `DEBUG`, работает ли HTTPS-редирект и защищённые cookie). Если
`DEBUG` включён или HTTPS не форсируется, журнал сам показывает блок «Проверьте боевые
настройки» с подсказками, что поправить в `.env`.

### Журнал заходов и событий

Внизу страницы — таблица **«Журнал заходов»**: когда, событие, IP-адрес, пользователь,
страница, подробности. Фильтры — по типу события и по IP-адресу; показываются последние
150 записей. Типы событий: «Заход на страницу», «Вход», «Неудачный вход», «Выход»,
«Заблокированный доступ», «Подозрительный запрос», «Событие» (события журнала: скачана
копия, сброшен пароль сотруднику, изменён список IP, восстановление из копии и т. п.).

* Кнопка **«Очистить журнал заходов»** удаляет только заходы на страницы; входы и события
  остаются — журнал подтверждает это сообщением.
* Записи старше **30 дней** удаляются автоматически (уборка запускается не чаще раза в час),
  поэтому журнал не растёт бесконечно.

### Защита от подбора пароля

Журнал сам блокирует подбор:

* **5** неудачных попыток входа для пары «адрес + логин» или **30** попыток с одного адреса
  (счёт идёт за последние **15 минут**);
* после этого вход с этого адреса временно закрыт, человек видит: «Слишком много неудачных
  попыток входа. Попробуйте снова через 15 минут.»;
* блокировка снимается сама через 15 минут после последней неудачной попытки;
* действующие блокировки перечислены на странице в красном блоке «Временные блокировки
  защитой от подбора пароля» — отдельно логины и отдельно адреса целиком.

Ничего настраивать не нужно: это работает всегда, независимо от настроек уведомлений.

### Доступ по IP-адресам

Блок **«Доступ по IP-адресам»** — ручные правила:

1. В поле «IP-адрес или подсеть» введите адрес (`203.0.113.10`) или подсеть
   (`203.0.113.0/24`).
2. Выберите правило: **«Разрешён (белый список)»** или **«Заблокирован (чёрный список)»**,
   при желании добавьте комментарий.
3. Нажмите **«Добавить правило»**. Правило появится в списке ниже; убрать его можно кнопкой
   **«Удалить»**.

Как это работает:

* чёрный список закрывает доступ с адреса: человек увидит страницу «Доступ с вашего IP-адреса
  запрещён администратором журнала», попытка попадёт в журнал как «Заблокированный доступ»,
  и придёт письмо (если почта настроена);
* если добавлен **хотя бы один белый список**, доступ разрешён только адресам из него
  (журнал предупреждает об этом синей строкой);
* локальные адреса **127.0.0.1** и **::1** разрешены всегда — ими нельзя запереть себя;
* более точное правило важнее общего (подсеть `/24` важнее `/16`);
* просроченные автоблокировки в проверке не участвуют и убираются из списка сами.

### Ручная блокировка и авто-блокировка сканеров

Блок **«Защита от сканеров»** показывает, что искали автоматические сканеры за последние
7 дней: статистику (заходы, свои адреса, неудачные входы, подозрительные, отказы), таблицу
**«Кто сканировал»** и список **«Что искали»**. В строке сканера есть две кнопки:

* **«Заблокировать на сутки»** — правило на 24 часа;
* **«Навсегда»** — бессрочная блокировка.

Подозрительными считаются запросы к адресам, которых в журнале не существует: `.env`, `.git`,
`wp-admin`, `wp-login`, `phpmyadmin`, `graphql`, `actuator`, `telescope`, `server-status`,
`info.php`, `config.json`, `backup.sql` и другие подобные. Такие запросы попадают в журнал
как «Подозрительный запрос», а в ответ сканер получает страницу «Такой страницы нет» —
никаких данных и настроек.

**Авто-блокировка (значения по умолчанию, меняются в `.env`):**

| Настройка | Значение | Что значит |
| --- | --- | --- |
| `AUTO_BLOCK_PROBES` | `1` (включена) | авто-блокировка работает |
| `AUTO_BLOCK_THRESHOLD` | `5` | столько подозрительных запросов с одного адреса достаточно |
| `AUTO_BLOCK_WINDOW_MINUTES` | `15` | за какое время считаются эти запросы |
| `AUTO_BLOCK_HOURS` | `24` | на сколько часов блокируется адрес |
| `AUTO_BLOCK_PRIVATE` | `0` | локальные и частные адреса автоматически **не** блокируются, чтобы не запереть себя |

Повторная автоблокировка того же адреса ставится **навсегда** (значит, прошлое правило
не подействовало). Об автоблокировке приходит письмо, а сама блокировка видна в списке правил,
где её можно снять кнопкой «Удалить».

### Почта для уведомлений

Блок **«Почта и уведомления»**: заполните **SMTP-сервер**, **Порт**, **Логин SMTP**,
**Пароль SMTP**, отметьте **STARTTLS** или **SSL** (что-то одно — журнал откажет, если
включены оба), укажите **«От кого»** и **«Кому (по одному адресу в строке)»**, включите
нужные уведомления:

* «Входы пользователей»;
* «Неудачные входы»;
* «Заблокированные адреса»;
* «Резервные копии»;
* «Учётки и пароли» (создание учётных записей и сброс паролей).

Пароль SMTP хранится в базе **зашифрованным**; оставьте поле пустым, чтобы не менять уже
сохранённый пароль. Письма приходят с темой «[Электронный журнал] …».

Проверка: введите адрес в поле «Проверка: отправить тестовое письмо» и нажмите
**«Отправить тест»**. Журнал ответит либо «Письмо отправлено на …», либо текстом ошибки
отправки. Пока не заданы сервер и получатели, уведомления не отправляются вовсе.
Если в `.env` задано `NOTIFY_EMAIL_BACKEND=console`, письма не отправляются, а пишутся
в лог приложения (`docker compose logs web`) — удобно для проверки на стенде.

### Доверие к заголовкам прокси

Переменная **`TRUST_PROXY_HEADERS`** (`0` по умолчанию):

* `0` — журнал берёт адрес клиента только из самого соединения (`REMOTE_ADDR`), заголовкам
  прокси не верит;
* `1` — адрес берётся из `X-Forwarded-For` (первый корректный адрес в цепочке), а если его
  нет — из `X-Real-IP`; дополнительно журнал начинает доверять заголовку `X-Forwarded-Proto`
  (то есть считает https-запрос https-запросом).

Включайте `1` **только** если перед журналом стоит свой обратный прокси (nginx, traefik),
который сам подставляет эти заголовки. Если журнал доступен напрямую из интернета,
включать нельзя: адрес в заголовке подделывается, и блокировки будут обходить.

### HTTPS, `SECRET_KEY` и fail2ban

* Публикуйте журнал только по HTTPS (сертификат Let's Encrypt и обратный прокси), затем
  в `.env`: `SECURE_SSL_REDIRECT=1`, `SESSION_COOKIE_SECURE=1`, `CSRF_COOKIE_SECURE=1`,
  `TRUST_PROXY_HEADERS=1`. При включённом редиректе журнал сам выставляет HSTS на год
  (`SECURE_HSTS_SECONDS=31536000`), если не задать своё значение.
* Не публикуйте порт 8000 во внешнюю сеть: оставьте доступ только через прокси
  (в `docker-compose.yml` можно написать `"127.0.0.1:8000:8000"`).
* **`SECRET_KEY`** — ключ журнала: им подписываются сессии и токены CSRF, им же шифруется
  пароль SMTP. Меняйте его, если ключ мог попасть к посторонним. Помните о последствиях:
  все, кто был в журнале, выйдут из него (сессии станут недействительными), а сохранённый
  пароль SMTP перестанет расшифровываться — его нужно заново ввести в разделе
  «Безопасность». Новый ключ: `python -c "import secrets;print(secrets.token_urlsafe(64))"`
  (не короче 50 символов), хранить в `.env`, файл `.env` не публиковать.
* Для блокировки сканеров и подбора пароля на уровне сервера есть готовый пример —
  `docs/fail2ban-journal.conf`: фильтр по подозрительным адресам, готовая секция jail
  (`maxretry = 5`, `findtime = 600`, `bantime = 86400`) и вариант настройки nginx
  (`limit_req`, передача `X-Forwarded-For` и `X-Real-IP`, закрытие служебных адресов).

## 12. Демонстрационный режим

### Зачем он нужен

Это витрина журнала: показать журнал без пароля и без риска для рабочих данных. Полезно
на совещании, при обучении сотрудников и при знакомстве с системой.

### Как показать журнал

1. В `.env` должно быть `DEMO_MODE=1` (в шаблоне `.env.example` стоит `0` — демо-режим
   по умолчанию выключен; при `DEBUG=1` он включается сам). После правки `.env`
   перезапустите контейнеры:

```bash
docker compose up -d
```

2. Откройте `/demo/` — страницу «Демо-режим» (у не вошедших в журнал она есть в меню,
   пока демо-режим включён; администратору тот же вход доступен из раздела
   «Демо-режим и демо-данные» по кнопке «Открыть демонстрацию»).
3. Нажмите **«Войти как методист»** или **«Войти как преподаватель»** — пароль не нужен.
   Журнал сообщит: «Демо-режим: вы вошли как … Это отдельная демонстрационная база —
   рабочий журнал она не затрагивает. Данные можно свободно менять.»
4. Год, полугодие и адрес в демонстрации переключаются так же, как в рабочем журнале.
   Выйти можно ссылкой **«Выйти из демонстрации»** в шапке.
5. Демонстрационные данные специально разнообразны: 50 учеников, 8 сотрудников (методист,
   администратор и шесть преподавателей), три адреса с кабинетами, программы и группы
   с разным составом, заполненное расписание вместе с разовыми занятиями и подменами, отметки
   за последние 28 дней с отсутствиями и опозданиями, темы занятий, участие в конкурсах
   и повышение квалификации педагогов.

### Что важно знать

* **Изменения не сохраняются.** Каждый запрос в демо-сессии выполняется в транзакции
  к демонстрационной базе и в конце откатывается, поэтому нажимать можно что угодно: в данных
  ничего не останется. Сессия демонстрации живёт до закрытия браузера.
* Демонстрация работает в **отдельной базе** (`DEMO_DB_NAME`, по умолчанию
  `school_journal_demo`) — в рабочем журнале демо-данных не бывает. Из демонстрации нельзя
  создать правило блокировки IP.
* В журнале заходов демо-вход помечается как «… (демонстрация)».

### Как обновить демо-данные

Данные готовятся автоматически: при старте контейнера с `DEMO_MODE=1` выполняется
`python manage.py demo_setup`. Вручную:

```bash
docker compose exec web python manage.py demo_setup
```

Команда создаёт демо-базу, если её ещё нет, применяет к ней миграции и заполняет данными;
повторный запуск ничего не дублирует — она скажет, что данные уже на месте, и напечатает
их состав. Полезные варианты: `demo_setup --skip-create` (база уже есть) и
`demo_setup --skip-migrate` (миграции применять не нужно).

Очистить демонстрацию (рабочий журнал не затрагивается):

```bash
docker compose exec web python manage.py clear_demo
```

Вместе с данными команда убирает адреса и кабинеты демо-базы, чтобы они не копились
от версии к версии. Адрес, за которым остались кабинеты, программы или занятия,
она не трогает и сообщает об этом отдельной строкой.

То же самое есть в интерфейсе: **«Демо-режим и демо-данные»** → «Открыть демонстрацию»
и «Очистить демо-базу» (с подтверждением).

### Почему демо-базу не мигрируют вручную

Отдельно запускать `migrate` для демонстрационной базы не нужно и не следует:

* обычная команда `docker compose exec web python manage.py migrate` применяет миграции
  **только к рабочей базе** — данные журнала при этом остаются в своей базе, демонстрация
  туда не попадает;
* схему демо-базы создаёт и обновляет сам `demo_setup`: он запускает миграции отдельным
  процессом, в котором демо-база объявлена основной, поэтому демонстрация всегда получает
  ту же схему, что и рабочий журнал;
* после обновления журнала достаточно перезапустить контейнеры (`docker compose up -d --build`) —
  при `DEMO_MODE=1` демо-база обновится сама.

## 13. Что делать, если

### Потерян доступ главного администратора

Нужна учётная запись администратора — её создают командой (журнал при этом ничего не удаляет):

```bash
docker compose exec web python manage.py createsuperuser
```

Команда спросит логин (латиницей), почту (можно оставить пустой) и пароль дважды; учётная
запись создаётся с ролью «Главный администратор». Если учётная запись есть, но пароль забыт:

```bash
docker compose exec web python manage.py changepassword admin
```

Вместо `admin` — логин этой учётной записи. Затем войдите в журнал и проверьте остальные
учётные записи в разделе «Сотрудники УМО».

### Экран первой настройки появился на рабочем журнале

Это значит, что в подключённой базе нет **ни одного активного администратора** (роль «Главный
администратор» или «Администратор», либо суперпользователь Django, и учётная запись включена).
Пока такого нет, любая страница ведёт на `/setup/`.

Типичные причины: всех администраторов выключили или понизили в роли; журнал подключён
к другой (новой или пустой) базе — например, изменили `POSTGRES_DB` в `.env`.

Что делать:

1. Проверьте, какая база подключена, и что она читается:

```bash
docker compose exec web python manage.py healthcheck
```

   Строка «[OK] База данных: соединение есть (postgresql, school_journal)» называет базу.
2. Создайте администратора: `docker compose exec web python manage.py createsuperuser`
   (см. выше) и войдите.
3. Откройте «Сотрудники УМО», снимите галочку «Выключить учётную запись» у нужных людей
   и при необходимости верните роль «Администратор».
4. Если вы поняли, что журнал подключён не к той базе, верните прежнее значение
   `POSTGRES_DB` в `.env` и перезапустите контейнеры:

```bash
docker compose up -d
```

Свои данные при этом никуда не пропадают: журнал показывал другую базу, а не удалял прежнюю.

### После обновления журнал не открывается

1. Посмотрите логи приложения и базы:

```bash
docker compose logs --tail 200 web
docker compose logs --tail 100 db
```

2. Запустите самопроверку — она называет причину:

```bash
docker compose exec web python manage.py healthcheck
```

   Ожидается «Checks: 11, errors: 0». Частые строки: «не применено миграций: N» (лечится
   командой `docker compose exec web python manage.py migrate`), «не найдены файлы» (статика:
   `docker compose exec web python manage.py collectstatic --noinput`), «не собираются шаблоны»
   (файлы проекта заменены не полностью — перезалейте версию).
3. Если в логах «Не задан SECRET_KEY…», «Не задан ALLOWED_HOSTS…» или жалоба на короткий
   `SECRET_KEY` — поправьте `.env` и перезапустите:

```bash
docker compose up -d
```

4. Откройте журнал и нажмите **Ctrl+F5** (принудительное обновление страницы).
5. Если проще откатиться: верните прежние файлы проекта и выполните
   `docker compose up -d --build`. Данные в томе `postgres_data` при обновлении и откате
   файлов не удаляются. Если что-то испортилось в данных — восстановите копию (раздел 5).

### Кончилось место на диске

1. Посмотрите, что занимает место (тома `postgres_data` и `media_data` — самые крупные):

```bash
docker system df -v
```

2. Удалите ненужные файлы резервных копий, которые лежат на сервере, и старые архивы
   на хосте. Чистить можно и журнал заходов: «Безопасность» → **«Очистить журнал заходов»**
   (записи старше 30 дней журнал и сам удаляет автоматически).
3. **Не удаляйте тома.** Команда `docker compose down -v` удаляет том с базой данных вместе
   со всеми данными — это не способ освободить место.
4. После освобождения места перезапустите приложение и проверьте его:

```bash
docker compose restart web
docker compose exec web python manage.py healthcheck
```

### База недоступна

1. Проверьте состояние контейнеров (у `db` должно быть `healthy`):

```bash
docker compose ps
```

2. Проверьте саму базу:

```bash
docker compose exec db pg_isready -U school_journal
```

3. Посмотрите логи базы и приложения:

```bash
docker compose logs --tail 200 db
docker compose logs --tail 200 web
```

4. Перезапустите базу (данные сохраняются):

```bash
docker compose restart db
```

5. Если база поднялась, но журнал всё ещё ругается, перезапустите и приложение, затем
   выполните `docker compose exec web python manage.py healthcheck`. Пароль, пользователь
   и имя базы берутся из `.env` (`POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`).

### Письма не приходят

1. Откройте **«Безопасность»** → блок **«Почта и уведомления»**. Должны быть заполнены
   «SMTP-сервер» и «Кому» (по одному адресу в строке), и включены нужные галочки уведомлений.
   Пока сервер и получатели не заданы, журнал не отправляет ничего.
2. Нажмите **«Отправить тест»**. Ответ «Письмо отправлено на …» означает, что настройки
   верны, и дело в получателе (папка «Спам», фильтры почтового сервера). Ответ «Ошибка
   отправки: …» называет причину — чаще всего неверный пароль SMTP, порт или режим шифрования.
3. STARTTLS и SSL нельзя включать одновременно — форма не сохранится.
4. Проверьте, каким транспортом отправляются уведомления: при `NOTIFY_EMAIL_BACKEND=console`
   в `.env` письма не отправляются, а пишутся в лог приложения:

```bash
docker compose logs --tail 100 web
```

5. Пароль SMTP хранится в базе зашифрованным ключом `SECRET_KEY`. Если ключ меняли, пароль
   нужно ввести заново.

### Забыт пароль сотрудника

Администратор задаёт новый пароль, не зная старого:

* **сотрудник УМО** (методист или администратор): «Сотрудники УМО» → ФИО сотрудника → блок
  **«Смена пароля»** → **«Сменить пароль»**;
* **преподаватель**: «Преподаватели» → **«Изменить данные и пароль»** → блок **«Смена пароля»**
  → **«Сохранить новый пароль»**.

Новый пароль один раз показывается в жёлтом блоке на странице списка — скопируйте его кнопкой
«Скопировать» и передайте человеку. Сам сотрудник может сменить пароль в «Мои данные», если
помнит текущий.

### Нужно удалить учебный год вместе с данными

**Сначала скачайте резервную копию** («Резервная копия» → «Скачать резервную копию»): удаление
года необратимо, вместе с ним уходят его полугодия, программы, группы, занятия и отметки.

В интерфейсе журнала кнопки удаления года **нет** — в разделе «Учебные периоды» год только
создаётся, а у полугодий правятся даты. Год удаляется в **«Админке Django»**:

1. Откройте «Админка Django» (адрес задаётся переменной `ADMIN_URL`).
2. Раздел «Электронный журнал» → **«Учебные годы»**.
3. Отметьте нужный год, выберите действие удаления и подтвердите. Админка покажет, что
   удалится вместе с годом.

То же самое можно сделать из консоли (сначала посмотрите, что уйдёт, потом удаляйте):

```bash
docker compose exec web python manage.py shell -c "from journal.models import AcademicYear, Subject, Group, Schedule, Attendance; y=AcademicYear.objects.get(start_date__year=2024); print(y.title, 'полугодий:', y.terms.count(), 'программ:', Subject.objects.filter(term__year=y).count(), 'групп:', Group.objects.filter(term__year=y).count(), 'занятий:', Schedule.objects.filter(group__term__year=y).count(), 'отметок:', Attendance.objects.filter(schedule__group__term__year=y).count())"
```

Убедившись, что это тот самый год, удалите его:

```bash
docker compose exec web python manage.py shell -c "from journal.models import AcademicYear; AcademicYear.objects.get(start_date__year=2024).delete()"
```

Учтите: админка Django и консоль удаляют год каскадом вместе со всем содержимым и не
проверяют, есть ли в его полугодиях группы. Правило «сначала удалите или перенесите группы»
действует только у действия удаления внутри самого журнала.

### Восстановление из копии пошло не так

1. Посмотрите, что именно применилось. После восстановления журнал выводит сравнение
   «в копии N, было M» по разделам (ученики, программы, группы, занятия, отметки, темы,
   конкурсы, курсы педагогов) и сообщает, сколько записей восстановлено.
2. Проверьте журнал:

```bash
docker compose exec web python manage.py healthcheck
```

   При необходимости примените миграции: `docker compose exec web python manage.py migrate`.
3. Если данные заменились не тем файлом, восстановите более раннюю копию — режим
   **«Добавить и обновить»** ничего не удаляет и безопаснее, чем «Полностью заменить».
   Если копии, снятой до неудачного восстановления, нет, данные, удалённые режимом «Полностью
   заменить», вернуть нечем — поэтому копию снимают **до** любых работ.
4. Если копия не читается, журнал ничего не меняет и объясняет причину: «Файл не похож
   на резервную копию журнала…», «Копия версии N не поддерживается: текущий формат — 10»,
   «Копия повреждена или неполна: нет обязательных разделов…», «Файл не является корректным
   JSON…». Проверьте, что это тот файл (`school_journal_backup_ГГГГММДД_ЧЧММ.json`
   или `.json.enc`) и что он не изменялся.
5. Для зашифрованной копии (`.json.enc`) нужна **та же** парольная фраза, с которой её
   скачивали: «Неверная парольная фраза или файл повреждён.» Парольная фраза нигде
   не сохраняется.
6. Помните особенности режима «Полностью заменить»: учётные записи людей не удаляются —
   они только добавляются и обновляются, а часть копии с главным администратором пропускается
   («В копии есть главный администратор — эта часть пропущена»).

## 14. Короткий чек-лист выкладки

Порядок действий при развёртывании рабочего журнала:

1. Проверьте `.env`: `DEBUG=0`, свой `SECRET_KEY` (50+ символов), свои домены
   в `ALLOWED_HOSTS`, `DEMO_MODE=0`, при работе за прокси — `TRUST_PROXY_HEADERS=1`.
2. Соберите и запустите журнал:

```bash
docker compose up -d --build
```

3. Убедитесь, что контейнеры подняты, а база отвечает:

```bash
docker compose ps
docker compose exec db pg_isready -U school_journal
```

4. Прогоните самопроверку — ожидается «Checks: 11, errors: 0»:

```bash
docker compose exec web python manage.py healthcheck
```

5. Откройте журнал по своему адресу и войдите. На чистой базе заполните экран первоначальной
   настройки `/setup/`; если доступ потерян, создайте администратора:

```bash
docker compose exec web python manage.py createsuperuser
```

6. Сразу после настройки скачайте резервную копию: **«Резервная копия»** → «Скачать резервную
   копию» (при желании — с парольной фразой).
7. Заведите учебный год и проверьте даты полугодий: **«Учебные периоды»**.
8. Создайте сотрудников УМО (**«Сотрудники УМО»**) и преподавателей (**«Преподаватели»**),
   сразу передайте им логины и пароли — пароль показывается только один раз.
9. Заполните справочники: при необходимости адреса и кабинеты (в «Админке Django»), учеников,
   программы, группы с составом, расписание. Данные прошлого полугодия перенесите кнопкой
   «Перенести из другого полугодия».
10. Настройте почту уведомлений в разделе «Безопасность» и проверьте её кнопкой
    «Отправить тест».
11. При публикации в интернете включите HTTPS-флаги (`SECURE_SSL_REDIRECT=1`,
    `SESSION_COOKIE_SECURE=1`, `CSRF_COOKIE_SECURE=1`), не публикуйте порт 8000 наружу
    и, при желании, поставьте fail2ban по примеру `docs/fail2ban-journal.conf`.
12. Проверьте выгрузки (**«Выгрузка в Excel»**) и расписание картинкой — так видно, что данные
    и права заполнены верно.

## 15. Отсутствия преподавателей и подмены

Преподаватель может заболеть или уехать в командировку — в эти дни он занятия не ведёт.
Чтобы журнал не считал такие занятия состоявшимися, сотрудник УМО отмечает **период
отсутствия** в отдельном разделе **«Отсутствия»** (`/absences/`). В меню это подраздел
**«Преподавателей»**: он стоит сразу под ними, с отступом.

### Где вносить

1. Откройте **«Отсутствия»** → кнопка **«Добавить отсутствие»**. Тот же переход есть
   в списке преподавателей: кнопка **«Отсутствие»** открывает форму с уже выбранным
   преподавателем (`/absences/add/?teacher=<pk>`).
2. Заполните форму:

| Поле | Что это |
| --- | --- |
| `Преподаватель` | кто отсутствует (обязательно) |
| `С` | первый день отсутствия (обязательно) |
| `По` | последний день отсутствия (обязательно). **Обе даты входят в период:** «с 12.10 по 20.10» — это 9 дней |
| `Причина` | `Командировка`, `Больничный` или `Другое` (по умолчанию — `Больничный`) |
| `Примечание` | свободный текст, необязательно; подсказка-пример — «Например: справка из поликлиники» |

3. Нажмите **«Сохранить»**. Журнал подтвердит: «Отсутствие добавлено:
   Больничный с 13.01.2025 по 17.01.2025.»

Внесённые периоды видны в таблице списка: столбцы «Преподаватель», «С», «По», «Причина»,
«Примечание», «Кто и когда внёс» и кнопки **«Подмены»**, **«Изменить»** и **«Удалить»**.
Кнопка **«Подмены»** открывает страницу подмен сразу на весь период (см. ниже), «Изменить» —
форму периода. Период, который
идёт сегодня, помечен значком «отсутствует сейчас». Список фильтруется по преподавателю
и переключателем **«Период»** (по умолчанию — «Только текущие и будущие», второй вариант —
«Все периоды, включая прошедшие»), сортируется по дате начала (текущие и ближайшие первыми,
прошедшие следом) и выводится постранично, как остальные списки («10, 25, 50, 100» записей
на страницу — см. шаг 3 раздела 7). Если периодов ещё нет, на месте таблицы написано
«Отсутствий пока нет. Нажмите «Добавить отсутствие» — например, когда у преподавателя
больничный.». Правка сохраняется сообщением «Отсутствие обновлено: …», удаление спрашивает
подтверждение на странице «Удаление отсутствия» и сообщает «Отсутствие удалено.».

**Где видно отсутствие.** В списке преподавателей у отсутствующего педагога стоит значок
«отсутствует», а в его карточке — компактная строка **«Отсутствует: Больничный с 13.01.2025
по 17.01.2025»** со ссылкой **«Отсутствия»** (открывает раздел с фильтром по этому
преподавателю) и кнопкой **«Поставить подмену»**: она открывает недельный журнал на неделю,
в которую попадает начало периода, — там отменённые занятия и та же кнопка. Карточка
показывает только текущий или ближайший будущий период; полностью прошедшие периоды видны
в разделе «Отсутствия». Формы для внесения отсутствий в карточке нет — периоды вносят
и правят только в разделе.

**В админке Django** модель тоже зарегистрирована («Электронный журнал» → «Отсутствия
преподавателей»): список периодов, фильтр по причине, поиск по ФИО преподавателя
и иерархия по дате начала.

**Кто имеет доступ.** Вносить, править и удалять отсутствия может только сотрудник УМО:
методист, администратор и главный администратор. У преподавателя этого раздела в меню нет,
поэтому на попытку открыть или отправить форму журнал ответит «Недостаточно прав для этого
раздела.». Отметку об отсутствии себе преподаватель поставить не может — об этом просит
методиста.

### Какие проверки делает журнал

* **Дата «По» не раньше даты «С».** Если перепутать даты, появится ошибка: «Дата «по»
  (10.01.2025) раньше даты «с» (13.01.2025).»
* **Периоды одного преподавателя не пересекаются.** Попытка добавить второй период,
  накрывающий первый, отклоняется: «У преподавателя уже отмечено отсутствие «Больничный»
  с 13.01.2025 по 17.01.2025: периоды не должны пересекаться.» Границы входят в период,
  поэтому «с 13.01 по 17.01» и «с 17.01 по 20.01» — пересечение, а «с 18.01 по 20.01» —
  уже нет. У разных преподавателей периоды друг другу не мешают: у каждого свой список.
* Если форма не прошла проверку, запись не сохраняется: страница формы («Новое отсутствие»
  или «Отсутствие · ‹ФИО›») возвращается с текстом ошибки у нужного поля, и период можно
  поправить и сохранить снова.

### Что происходит с занятиями

Отсутствие ничего не удаляет: расписание остаётся на месте, уже поставленные отметки тоже
никуда не деваются. Меняется только учёт — занятие на дату отсутствия считается
**отменённым**:

* **«Посещаемость»** (`/weeks/`) — у занятия появляется пометка «занятие
  отменено» и строка «Отсутствие: Больничный с 13.01.2025 по 17.01.2025», а в шапке
  недели — отдельная строка «отменено: N ч» и «· отменённых занятий: N».
* **«Мои занятия» преподавателя** (`/teacher/`) — вместо ссылки на отметки написано
  «Занятие отменено: отметки недоступны», рядом виден период отсутствия, а в шапке —
  та же строка «отменено: N ч».
* **«По неделям: темы и часы»** (`/teacher/week/`) — у занятия стоят «отменено: N акад. ч.»,
  значок «занятие отменено» и подпись «Занятие отменено: отметки по нему не ставятся
  и в часах не учитываются.»
* **Страница отметок** занятия — красная плашка «Отсутствие: Больничный с 13.01.2025
  по 17.01.2025» и пояснение «Занятие не считается состоявшимся: отметки на эту дату
  не сохраняются и в часах не учитываются.»; переключатели отметок и кнопка
  «Сохранить посещаемость» при этом выключены. Если отправить форму в обход (например,
  со старой открытой страницы), журнал ответит «Занятие отменено: Больничный с 13.01.2025
  по 17.01.2025. Отметки не сохраняются.» и ничего не запишет.
* **Календарь занятий группы** на странице отметок — дни внутри периода подсвечены
  красным, а в подсказке дня написано «Отсутствие: Больничный с 13.01.2025 по 17.01.2025».
* **«Расписание»** (`/schedule/`) — рядом с преподавателем красная пометка «отсутствует:
  Больничный 13.01.2025–17.01.2025». У обычного занятия (без даты) показывается ближайший
  период внутри полугодия группы, у разового — только если его дата попадает в период.
* **«Темы занятий»** (`/topics/`) — тема отменённого занятия заменена пометкой «занятие
  отменено», а его часы вынесены в отдельную строку «отменено: N ч» и в «Итого часов»
  не входят.

**Часы.** Академические часы отменённых занятий исключаются из плана и из итогов и всегда
показываются отдельной строкой «отменено: N ч» — прибавлять их к остальным не нужно.
Пометки не «застывают»: если период отсутствия удалить, занятия снова считаются
состоявшимися, а часы возвращаются в общий итог.

### Как поставить подмену

Подмена — это обычное занятие на конкретную дату, которое ведёт другой преподаватель.
Удобнее всего поставить её кнопкой **«Поставить подмену»**:

* в **карточке отсутствующего преподавателя** — кнопка открывает недельный журнал
  на неделю, в которую попадает начало периода;
* **рядом с отменённым занятием** — в «Посещаемости по неделям» (и в «По неделям: темы
  и часы»), а также на странице отметок отменённого занятия.

С отменённого занятия кнопка открывает форму нового занятия с уже заполненными группой,
кабинетом, днём недели, датой, временем и полем **«3. Кого заменяют (для подмены)»** — остаётся
выбрать заменяющего. Галочка **«2. Подмена (заменяющий преподаватель)»** в этой форме уже
отмечена: занятие будет помечено значком «подмена». На проверку занятости заменяющего эта
отметка не влияет. Если подмена на это место **уже стоит**, кнопки нет: в карточке занятия
написано «Занятие проведёт заменяющий: ‹ФИО›.» и короткая строка «Отметки и часы — за заменяющим
преподавателем.» — так журнал не даёт поставить вторую подмену на то же место.

Вручную то же занятие создаётся так:

1. **«Расписание»** (`/schedule/`) → «Добавить занятие».
2. Заполните «Группа», «Начало занятия», «Окончание занятия» и «Кабинет».
3. В поле **«Дата разового занятия»** укажите дату из периода отсутствия — тогда занятие
   попадёт ровно на этот день.
4. В поле **«Преподаватель занятия»** выберите заменяющего, а в поле **«3. Кого заменяют»** —
   того, кого он заменяет (необязательно: без него подпись «Подмена для …» ищется по месту).
5. Сохраните занятие.

Что при этом проверяется:

* **Занятость отсутствующего преподавателя не мешает.** На дату отсутствия журнал не
  считает его занятым, поэтому подмену можно поставить даже на то время, когда у него
  по расписанию идёт другое занятие.
* **Занятость заменяющего, кабинет и группа проверяются как обычно.** Если у заменяющего
  в это время уже есть занятие, форма не сохранится: журнал напишет, у кого и когда «уже
  занятие». То же — про занятый кабинет и про группу, у которой в это время уже есть
  занятие. Про уже стоящую подмену на том же месте форма скажет отдельно: «На это время
  у группы уже есть занятие: 05.10.2026, 09:00 — Иванов И. И. (подмена). Откройте его
  в расписании, чтобы изменить, или выберите другое время.»
* **Заменяющий не должен сам отсутствовать.** Если у выбранного преподавателя на эту дату
  отмечено отсутствие, форма не сохранится: «Иванов И. И. отсутствует 05.10.2026: Больничный
  с 05.10.2026 по 11.10.2026. Подмену проведёт другой преподаватель.»
* **Заменяющий — только из программы.** Список заменяющих у каждой строки свой: основной
  преподаватель программы и дополнительные из карточки программы (у поля «Один заменяющий на
  все дни» — объединение по строкам, поэтому оно подставляется только туда, где этот
  преподаватель программу ведёт). Чужого преподавателя строка не примет: занятие может вести
  только преподаватель программы.
* **Галочка «2. Подмена (заменяющий преподаватель)» проверку не снимает.** Она только
  помечает занятие значком «подмена»: занятость заменяющего по времени проверяется как
  обычно. Чтобы провести подмену в уже занятое у заменяющего время, поставьте отдельную
  галочку **«1. Не учитывать занятость преподавателя»** — это единственная отметка,
  снимающая проверку по времени. Занятость кабинета и группы проверяется всё равно.
* Сообщение о сохранении занятия короткое — «Занятие добавлено.»: отметки формы
  в нём не перечисляются (видно по самому занятию: значок «подмена» в расписании
  и занятое время преподавателя).

Подмена — это отдельное занятие: обычное занятие группы на дату отсутствия остаётся
в расписании, но считается отменённым, а занятие ведёт заменяющий преподаватель.

### Подмены сразу на весь период

Ставить подмены по одному занятию долго, поэтому в строке периода есть кнопка **«Подмены»**
(`/absences/<id>/substitutions/`). Она открывает страницу со всеми занятиями преподавателя,
которые попадают в период:

* обычные недельные занятия показаны **по каждому вхождению дня недели** в период — конкретными
  датами, разовые — своей датой; занятие, уже отменённое отсутствием, тоже в списке: именно его
  и заменяют;
* по каждой строке видно дату, день недели, время, группу, программу и кабинет;
* у каждой строки — выбор заменяющего, галочка **«Ставить»** (отмечена по умолчанию) и галочка
  **«Не учитывать занятость»**;
* сверху — поле **«Один заменяющий на все дни»**: выберите преподавателя, и он подставится во все
  строки (типичный случай). В отдельных строках выбор можно поменять, а лишние строки — снять
  галочкой «Ставить».

**Конфликты видно заранее.** Строку, которую нельзя сохранить, журнал подсвечивает и пишет
причину: «Занят: 10:00–11:30 — Программа · Группа 3» (у заменяющего в это время другое занятие),
«Кабинет «Кабинет 1» занят: …», «У группы уже есть занятие: …», «Заменяющий отсутствует в этот
день: Больничный с 13.01.2025 по 17.01.2025». Счётчики сверху показывают, сколько занятий будет
создано, сколько пропущено и сколько строк с конфликтами.

Занятость заменяющего снимается галочкой **«Не учитывать занятость»** именно у этой строки;
занятость кабинета и группы не снимается ничем — такую строку нужно снять галочкой «Ставить».
Если отправить строку с конфликтом, ничего не сломается: строка пропускается, а в сообщении
перечислены даты и причина — например, «Пропущены из-за конфликтов (2): 13.01.2025, 20.01.2025.».
Кнопка **«Проверить конфликты»** пересчитывает страницу по выбранным значениям и ничего не
сохраняет (ею можно пользоваться, если браузер не выполняет скрипты).

**Почему повторный запуск не создаёт дублей.** Подмена — это разовое занятие, а у группы на одну
дату и одно время может быть только одно разовое занятие. Поэтому журнал проверяет место (группа,
дата и время начала): если подмена там уже стоит, строка пропускается с сообщением «Уже стояли
подмены (2): 13.01.2025, 20.01.2025.». После сохранения журнал пишет «Создано подмен: N,
пропущено: M.» и возвращает в раздел «Отсутствия». Сохранение идёт одной транзакцией: либо все
выбранные строки, либо ни одной.

Если заменяется **разовое** занятие, второе такое же создать нельзя: журнал меняет
преподавателя прямо в этой записи и сохраняет прежнего в поле «Кого заменяют» (см. ниже).

### Раздел «Подмены»: посмотреть и найти

В меню появился подраздел **«Подмены»** (`/substitutions/`) — сразу под «Отсутствиями», с тем же
отступом. Это журнал уже поставленных подмен активного полугодия и адреса: **создавать здесь
нельзя**, только смотреть и искать.

| Колонка | Что в ней |
| --- | --- |
| Дата, день недели, время | когда и во сколько ведёт занятие заменяющий |
| Группа, программа, кабинет | куда идти; под кабинетом — адрес |
| Заменяющий | кто ведёт; если он сам отмечен отсутствующим на эту дату — янтарная пометка «заменяющий тоже отсутствует: Командировка с 12.10.2026 по 18.10.2026» |
| Кого заменяет | ФИО заменяемого и период его отсутствия: «Иванов И. И. · Больничный с 05.10.2026 по 11.10.2026». Если пару определить нельзя, стоит «—» с пояснением «кого заменяют, определить не удалось» |
| Действия | **«Отметки»** — страница отметок этого занятия на его дату; **«Изменить»** — форма занятия |

Фильтры: **«Заменяющий»**, **«Кого заменяют»**, **«С даты»**, **«По дату»**, **«Группа»** и
кнопка **«Сбросить»**. Сортировка — по дате по убыванию (сначала свежие и будущие подмены),
вывод постраничный, как в остальных списках. Если подмен ещё нет, на месте таблицы написано:
«Подмен пока нет. Их ставят в разделе «Отсутствия» — «Подмены» на весь период, либо с отменённого
занятия в недельном журнале.». Доступ у раздела такой же, как у «Отсутствий»: только сотрудники
УМО, преподавателю в меню его не видно.

### Отметки на подмене

Подмена — обычное занятие на конкретную дату, поэтому **отметки на ней доступны**: страница
отметок открывается, статусы и тема сохраняются. Отмечать может сотрудник УМО и сам заменяющий
преподаватель (занятие записано на него). У отсутствующего преподавателя этой подмены нет ни в
«Моих занятиях», ни в «По неделям», и открыть её страницу отметок он не может — журнал ответит
«Такой страницы нет».

**Часы.** Академические часы подмены идут заменяющему: занятие входит в его план и в общий итог
недели. У отсутствующего преподавателя отменённое занятие по-прежнему исключено и показано
строкой «отменено: N ч».

**Что видит заменяющий.** На своих страницах («Мои занятия», «По неделям: темы и часы», страница
отметок) у подмены стоит подпись **«Подмена для Иванов И. И. · Больничный с 05.10.2026 по
11.10.2026»** — сразу видно, кого он заменяет и на какой период.

**Правило про отсутствующего заменяющего.** Поставить подмену тому, у кого на эту дату отмечено
отсутствие, нельзя: форма занятия не сохранится и напишет «Иванов И. И. отсутствует 05.10.2026:
Больничный с 05.10.2026 по 11.10.2026. Подмену проведёт другой преподаватель.». Если такая запись
уже есть (её внесли до появления правила), карточка недели и строка списка «Подмены» показывают
предупреждение **«Заменяющий тоже отсутствует: …»**, а занятие считается несостоявшимся.

### Поле «Кого заменяют»

Кого заменяет подмена, журнал хранит **у самого занятия** — в поле «Кого заменяют». Оно
заполняется само, когда подмену ставят из раздела «Отсутствия» или кнопкой «Поставить подмену»,
и его же можно указать вручную в форме занятия — поле **«3. Кого заменяют (для подмены)»**,
необязательное.

* Список в форме — действующие преподаватели; значение из ссылки кнопки «Поставить подмену»
  подставляется автоматически, а мусор и отключённый преподаватель просто игнорируются.
* Подпись «Подмена для …» берётся из этого поля: если исходное занятие потом перенесли на другое
  время или в другой день, подпись не пропадает.
* У подмен, поставленных до появления поля, оно пустое — для них работает прежний поиск по
  совпадению группы, даты и времени, поэтому старые записи подписаны как раньше.
